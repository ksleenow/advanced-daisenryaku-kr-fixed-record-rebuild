# v019 최초 격리 8x8 글리프 체크포인트

## 경계 교정

- 원본 68K 로더 `0x0081FE`, `0x0106AC`는 `D3=0x547`을 설정한다.
- 업로드 루프는 `D3+1`바이트를 소비하므로 실제 8x8 블록은
  `0x3850E..0x38A55`, 정확히 `0x548`바이트다.
- 물리 슬롯은 169개(`0x00..0xA8`)지만, 레코드 코드 `0xA7..0xFF`는
  제어/다중바이트 충돌이 실행으로 입증되었으므로 계속 금지한다.
- 과거의 `0xA90/338글리프` 해석은 폐기한다.

## 변경

- 부모: `out/fixed-record-kana-kanji-phonetic-v018.md`
- 출력: `out/fixed-record-8x8-single-slot-v019.md`
- 8x8 슬롯 `0x49`의 `ア` 비트맵만 M8x8 기반 `아`로 교체했다.
- 문자열, 레코드, 포인터, 코드, VRAM 배치, 16x16 글리프는 변경하지 않았다.
- 빌더는 명시한 `--small-font-index`만 바꾸며 `0xA7` 이상을 거부한다.

## 실행 스모크

BizHawk 2.11.1 / Genplus-gx에서 기존 세이브 상태의 지도 메뉴, 지도 하단
상태창, 개발 화면을 각각 불러 30프레임 진행했다. 세 화면이 정상 표시됐고
에뮬레이터는 응답 상태를 유지했다.

이 ROM은 대량 8x8 치환의 기준이 아니라, 단일 슬롯 확장 검증의 부모로만
사용한다. 다음 슬롯은 항상 한 개씩 추가하고 최초 표시, 포커스 진입/이탈,
재진입, 지도 복귀, 표준 시나리오 진입을 확인한다.
