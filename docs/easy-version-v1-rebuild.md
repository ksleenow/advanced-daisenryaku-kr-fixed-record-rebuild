# EASY VER V1 재빌드 기록

> **출처 및 프로젝트 구분:** 이 EASY VER V1은 본 저장소에서 처음부터
> 재구축한 한글판을 기반으로 만든 것이 아니다. 사용자가 별도로 제공한
> **다른 제작자의 완성 한글 패치 ROM**을 로컬 입력으로 삼아 난이도만
> 변형한 파생 시험판이다. 따라서 EASY VER V1 전체를 본 프로젝트의 독자
> 한글화 결과물로 주장하거나 배포해서는 안 된다. 본 저장소가 직접 수행한
> 범위는 아래에 기록한 난이도 변경의 조사·패치·검증뿐이다. 이 작업이 끝난
> 뒤에는 본 저장소의 일본판 원본 기반 고정 레코드 한글화 작업으로 복귀한다.

## 목적과 적용 원칙

EASY VER는 외부 한글 패치 ROM과 본 프로젝트의 자체 한글화 본편 모두에서
분리된 파생 빌드다. 외부 한글판이 갱신될 때마다 사용자가 적법하게 보유한
새 로컬 ROM을 입력으로 다시 생성하며, EASY VER의 변경을 자체 한글화 본편
ROM에 역으로 합치지 않는다.

- 모든 혜택은 `USER(1)` 진영에만 적용한다.
- `COM` 및 중립 진영 데이터와 실행 경로는 원본 그대로 둔다.
- 시나리오 레코드의 길이와 개수는 변경하지 않는다.
- 원본 ROM과 완성 ROM은 저장소에 올리지 않는다.
- 외부 한글 패치의 번역문·글꼴·그래픽을 본 프로젝트 자산으로 이관하지 않는다.
- EASY VER 작업에서 확인한 난이도 패치 기법만 독립적인 기술 기록으로 남긴다.
- 빌드 전 입력 SHA-256, 빌드 후 변경 허용 범위와 메가드라이브 체크섬을
  반드시 확인한다.

## V1 확정 사양

| 항목 | 확정값 | 적용 범위 |
|---|---:|---|
| 유닛 상한 | 기존 USER 상한 `+5` | 물리 풀 한계 또는 개별 상한에 걸리는 시나리오는 건너뜀 |
| 시작 군자금 | `50,000` | 각 시나리오 USER 진영만 |
| 전투 경험치 | 원본 계산값 `×6` | 경험치를 받는 실제 유닛의 소유 진영이 USER일 때만 |
| 경험치 상한 | `250` | 원본 포화 처리 유지 |
| 개발 속도 | 변경 없음 | 미적용 |
| 타이틀 표기 | `EASY VER` | 기존 부제 8칸 영역 |

수익 배율 패치는 사용하지 않는다. 턴 정산 경로를 건드리는 대신 시작
군자금을 50,000으로 설정해 안정성을 우선했다.

## V1 최종 산출물 식별값

- 기준 한글 ROM SHA-256:
  `2C1F547239E5133423ADDA3A60196033582A4C6D37782FD9331046DD9C1A0FB2`
- 유닛 상한/군자금 적용 ROM SHA-256:
  `6E8F3A7534F17CCB78B9CD99B69B9CD5EF6B5242DF7F786C0B259E508BC15672`
- EASY VER 로고 적용 ROM SHA-256:
  `BB42981C0187D09B6EC3BD0BECF4A616D598A1046D7EA40CDC0BEE7BA8346925`
- EASY VER V1 최종 ROM SHA-256:
  `83F6FF3C223AD1D56ACD70D38AEBB49ED89C02369951C0C9BC81201DC4687FD0`
- 최종 메가드라이브 체크섬: `0xC3FE`
- 최종 ROM 크기: `4,194,304` 바이트

해시는 ROM 배포 수단이 아니라 로컬 산출물이 정확한지 확인하는 식별값이다.

## 재빌드 순서

1. 새 한글판 ROM의 SHA-256을 기록하고 별도 복사본에서 시작한다.
2. 시나리오 테이블을 다시 조사한다. V1에서는 `0x7EF28`, 레코드 `0x70`
   바이트, 44개였으나 새 본편 버전에서 동일하다고 가정하지 않는다.
3. 각 진영의 controller 바이트가 `USER(1)`인 레코드에만 유닛 상한 `+5`와
   시작 군자금 `50,000`을 기록한다.
4. 물리 유닛 풀 총합과 진영별 상한을 검사하고 한계를 넘는 시나리오는
   자동으로 건너뛴다.
5. 검증된 로고 빌더로 `EASY VER`를 적용한다. 부제 타일 이외의 타이틀
   그래픽이 바뀌면 빌드를 폐기한다.
6. `tools/easy/build_easy_exp_x6.py`를 실행해 USER 경험치 ×6 훅을 적용한다.
7. 체크섬, 변경 바이트 허용 목록, USER/COM 분리를 정적 검증한다.
8. 런타임에서 아래 회귀검증을 모두 통과한 뒤에만 최종본으로 승격한다.

## 경험치 훅의 핵심

원본 경험치 가산 지점은 `0xDFEE`이며 원본 바이트는
`DD2A000E61000004`이다. 실제 경험치 수령 유닛은 `A2`, 경험치 바이트는
유닛 레코드의 `+0x0E`, 소속 진영 번호는 `+0x0F`이다.

올바른 USER 판별 절차는 다음과 같다.

1. `A2+0x0F`에서 소속 진영 번호를 읽는다.
2. 런타임 진영표 `0xC800 + 진영번호×0x20`을 계산한다.
3. 해당 진영표의 controller 바이트 `+9`가 `1`인지 확인한다.
4. USER이면 원본 계산 경험치 `D6×6`, 아니면 원본 `D6`을 가산한다.
5. 원본 `0xDFF8` 포화 처리로 복귀해 최대 250을 유지한다.

### 실패 사례와 재발 방지

초기 시험 훅은 `A2`를 전투 구조체 주소 `$CD0C/$CD42`와 직접 비교했다.
그러나 `A2`는 그 구조체 내부에서 꺼낸 **실제 유닛 포인터**이므로 비교가
항상 실패했고, 게임은 안정적이었지만 경험치 배율이 전혀 발동하지 않았다.
향후에는 전투 구조체 주소로 소유권을 추정하지 말고 위의 유닛 `+0x0F`
소속 번호를 반드시 사용한다.

## 런타임 회귀검증

- USER 유닛 한 번 공격 후 경험치가 원본 계산값의 6배인지 확인한다.
- 불리한 지형/다수 격파 등 원본 가변 계산이 그대로 반영되는지 확인한다.
- COM 유닛 경험치가 원본과 같은지 확인한다.
- 공격 실행과 전투 종료 후 맵 복귀가 멈추지 않는지 확인한다.
- 턴 종료, 상대 턴, 다음 날 복귀가 정상인지 확인한다.
- 표준/캠페인 양쪽에서 시나리오 시작이 정상인지 확인한다.
- 유닛 생산 상한 `+5`와 시작 군자금 50,000을 서로 다른 시나리오에서
  확인한다.
- 타이틀의 `EASY VER` 및 주변 픽셀이 기준 한글판과 동일한지 확인한다.

## 다음 버전 운용

한글판 버전이 바뀌면 이 문서의 최종 ROM을 다시 패치하지 않는다. 반드시
새 한글판 ROM에서 시작해 각 단계의 예상 바이트와 SHA-256을 갱신한다.
패치 주소가 같아 보여도 예상 원본 바이트가 다르면 즉시 중단하고 재분석한다.
