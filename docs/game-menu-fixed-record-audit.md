# 게임 메뉴 고정 레코드 조사

일본판 Rev. A만을 기준으로 조사한다. ROM은 변경하지 않았다.

## 상태별 레코드

- `중止` 일반: `0xEF250`, 선택: `0xEF253`
- `ロード` 일반: `0xEF452`, 선택: `0xEF456`
- `セーブ` 일반: `0xEF45B`
- `降伏` 일반: `0xEF45F`, 선택: `0xEF463`

## 확인창 레코드 경계

- 저장 확인: `0xEF468..0xEF472`
- 읽기 확인: `0xEF473..0xEF47D`
- 응답 A: `0xEF47E..0xEF484`
- 응답 B: `0xEF485..0xEF489`

## 표시 루틴 추적 결과

- 저장 확인은 `0x11AAE`에서 `0xEF468`을 `A0`에 넣고 `0x11C66`을 호출한다.
- 읽기 확인은 `0x603C`와 `0x118F2`에서 `0xEF473`을 `A0`에 넣고
  `0x11C66`을 호출한다.
- `0x11C66`은 창을 초기화한 뒤 `0x8166`으로 레코드를 출력한다.
- `0x8166`은 첫 바이트를 `DBRA` 카운터로 사용하므로 실제 표시 셀 수는
  `첫 바이트 + 1`이다.
- `0x81C8..0x81DE`에서 한 셀을 읽는다. `0x00..0xFC`는 1바이트 글리프이고,
  `0xFD` 또는 `0xFE`는 다음 바이트와 합쳐 확장 글리프 한 셀을 만든다.
- 따라서 이 네 레코드의 카운터 뒤 페이로드는 제어값 혼합물이 아니라
  전부 표시 글리프다. `0x14`도 이 문맥에서는 선택지 좌우 패딩 글리프다.

확인창은 이제 제어값 오판 없이 번역할 수 있지만, 실제 셀 수와 총 바이트
길이를 모두 고정해야 한다. 확장 글리프를 넣으면 다른 1바이트 글리프 수를
조절해 레코드 전체 길이까지 보존해야 하므로, 별도의 화면 단위 후보에서만
수정한다.

동일 문구라도 초기 표시와 포커스 표시의 카운터 및 패딩이 다르다.
번역할 때는 각 레코드의 바이트 수, 글리프 수, 끝 패딩을 그대로 유지하고
일반/선택/선택 해제/재진입을 모두 검증한다.

## 번역 원칙

- 일본판 원문의 의미만 사용한다.
- `セーブ`, `ロード`처럼 일본판에서 가타카나인 항목은 먼저 음역 상태를
  보존하며, 화면별 의역은 모든 상태 레코드가 확인된 뒤 별도 후보에서 한다.
- 원본 레코드를 늘이거나 줄이지 않는다.
