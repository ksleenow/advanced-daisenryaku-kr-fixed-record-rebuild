# 남은 프로젝트 3번: 별도 문장용 폰트 뱅크 PoC

## 목적

v029에서 확정된 원본 16x16 한자음·가나 치환 영역과 8x8 가타카나 영역을
더 이상 변경하지 않고, 자연스러운 문장 번역에 사용할 별도 한글 폰트
뱅크의 기술적 가능성을 검증한다.

## 불변 기준

- 부모 ROM: `fixed-record-8x8-katakana-complete-v029.md`
- SHA-256: `93AB33A6CA42A52747670B314DCF8A2D3BBB90777D6DD6F3FD32181059471939`
- 기존 16x16/8x8 글리프, 문자열 레코드, 포인터, 코드, VRAM 배치를 잠근다.
- 일본판에서 영문인 문자열과 숫자를 그대로 보존한다.
- 실험 결과를 v029에 덮어쓰지 않는다.

## 단계

1. 1 MiB → 2 MiB 무데이터 확장과 헤더·체크섬만 검증
2. 원본 폰트 뱅크를 확장 영역에 복제하되 참조는 바꾸지 않음
3. 기존 렌더러의 폰트 소스 참조만 복제 뱅크로 전환
4. 신규 한글 글리프 한 글자와 고정 길이 레코드 한 곳 검증
5. 초기/포커스 인/포커스 아웃/재진입/지도 복귀 검증

각 단계는 앞 단계가 정적 검사와 실행 검사를 모두 통과한 뒤에만 진행한다.

## 1단계 허용 변경

- ROM 크기: `0x100000` → `0x200000`
- 확장 영역: `0x100000..0x1FFFFF`, 균일한 `0xFF`
- 체크섬: `0x18E..0x18F`
- ROM 종단 헤더: `0x1A4..0x1A7`, `0x000FFFFF` → `0x001FFFFF`

그 밖의 v029 앞쪽 1 MiB에서 변경이 발견되면 빌드를 거부한다.

## 2단계 복제 배치

- 16x16 원본: `0x03C86A`, `0x4800` bytes
- 16x16 복제: `0x100000`
- 8x8 원본: `0x03850E`, `0x548` bytes
- 8x8 복제: `0x105000`

두 복제 블록은 원본 블록과 SHA-256이 같아야 한다. 이 단계에서는 기존
폰트 참조, 실행 코드, 문자열 레코드, VRAM 업로드 길이를 변경하지 않는다.

## 픽셀 동일성 검증

BizHawk 2.11.1 / Genplus-gx에서 기존 읽기 전용 세이브스테이트 세 개를
각 후보에 로드했다. v030, v031, v032, v033의 캡처 해시는 모두 같았다.

- 지도 C 메뉴: `EA6B8E89C5151ECD3C6C6DF33599D6965F9DE2D2BB067557C04CB04E56293E01`
- 지도 하단 상태창: `3930F131F1D117BA737DCA28C7E80933D6654055A507AE546548BFC78A1F05F2`
- 개발 화면: `18D41FBB3DF9C224EBCD1E18502241E1C6608173D6C01328991DC586CF7BFEFA`

따라서 메가드라이브 68K가 확장 영역의 두 글꼴 뱅크를 정상적으로 읽으며,
동일 글꼴을 사용했을 때 기존 화면과 VRAM 결과가 변하지 않는 것이
실행 화면 단위로 확인됐다.

## 다음 안전 게이트

v033을 주소 전환 체크포인트로 보존한다. 다음 후보에서는 원본 글꼴이나
기존 레코드를 수정하지 않고, 확장 뱅크의 신규 슬롯 한 글자와 별도 시험
레코드 한 곳만 사용한다. 기존 코드값과 충돌하거나 고정 길이를 바꾸는
방식은 허용하지 않는다.

## v034: 신규 글리프·분리 레코드 표시 PoC

- 파일: `project-03-new-glyph-title-v034.md`
- SHA-256: `A7A3384783EED917DA10AF4BBB07CA030306E56C6C84997DA960DA14D7E686C4`
- 체크섬: `0x62AA`
- 신규 16x16 슬롯: `0x240=시`, `0x241=험`
- 신규 글리프 위치: `0x104800`, `0x104820`
- v034의 시험 레코드 `01 FE 42 FE 43`은 인덱스 계산이 한 칸
  어긋나 `0x23F=득`, `0x240=시`를 표시했다.
- 수정 시험 레코드: `0x106000`, `01 FE 43 FE 44`
  (`0x240=시`, `0x241=험`)
- 기존 레코드 `0x0EF423`: `01 FD 5A FD 5B`, 변경 없음
- 기존 레코드와 시험 레코드는 모두 정확히 5바이트·2표시 칸이다.
- 단일 참조 `0x0117F8`만 기존 레코드에서 시험 레코드로 전환했다.
- C 메뉴의 `자동` 세부 화면 제목에서 `시험`을 확인한다.

v034 역시 기존 세 실행 캡처 해시가 v030~v033과 모두 동일했다. 따라서
새 글리프와 새 레코드는 대상 화면 밖의 지도·하단 상태창·개발 화면을
변경하지 않았다. 다음 검증은 대상 화면의 초기 표시, 포커스 전환, 재진입,
지도 복귀다.

않았다.
