# 시작 전 옵션 고정 레코드 조사

일본판 Rev. A 원본만 읽어서 조사했으며 ROM은 변경하지 않았다.

## 메뉴 상태 테이블

`0x1016A`부터 각 항목은 `상태(2) + 표시 레코드 포인터(4) + 처리 함수
포인터(4)`인 10바이트 고정 엔트리다.

| 순서 | 상태 | 표시 레코드 | 처리 함수 |
|---:|---:|---:|---:|
| 0 | 0 | `0xEF41C` | `0x117AA` |
| 1 | 0 | `0xEF428` | `0x11E2C` |
| 2 | 0 | `0xEF42D` | `0x12064` |
| 3 | 0 | `0xEF433` | `0x1226E` |
| 4 | 0 | `0xEF43A` | `0x12386` |
| 5 | 0 | `0xEF441` | `0x1245A` |

이 테이블에는 별도의 포커스 문자열 포인터가 없다. 항목 선택 반전은 같은
표시 레코드를 다시 해석하거나 타일 속성을 바꾸는 경로일 가능성이 높으므로,
문자열을 복제해 해결하지 않는다.

## 표시 레코드

| 주소 | 일본판 원문 | 바이트 | 표시 칸 |
|---:|---|---:|---:|
| `0xEF41C` | ` 天候 ` | 7 | 4 |
| `0xEF423` | `天候` | 5 | 2 |
| `0xEF428` | `サウンド` | 5 | 4 |
| `0xEF42D` | ` 操作 ` | 6 | 4 |
| `0xEF433` | ` 索敵 ` | 7 | 4 |
| `0xEF43A` | ` 天候 ` | 7 | 4 |
| `0xEF441` | `システム` | 5 | 4 |

`0xEF41C`과 `0xEF423`은 같은 `天候`를 쓰지만 패딩과 표시 칸이 다른 별도
레코드다. 각각 메뉴와 옵션 화면 제목에서 참조되므로 합치거나 길이를 바꾸면
안 된다.

`0xEF44B`의 ` MUSIC`은 일본판부터 영문이므로 그대로 보존한다.

## 직접 참조 확인

- `0xEF41C`: 상태 테이블 `0x1016C`
- `0xEF423`: 날씨 화면 코드 `0x117F8`
- `0xEF428`: 상태 테이블 `0x10176`, 게임 메뉴 테이블 `0x6234`,
  사운드 화면 코드 `0x11EDA`
- `0xEF42D`: 상태 테이블 `0x10180`, 게임 메뉴 테이블 `0x623E`
- `0xEF433`: 상태 테이블 `0x1018A`, 게임 메뉴 테이블 `0x6248`
- `0xEF43A`: 상태 테이블 `0x10194`, 게임 메뉴 테이블 `0x6252`,
  날씨 화면 코드 `0x10F30`
- `0xEF441`: 상태 테이블 `0x1019E`, 게임 메뉴 테이블 `0x625C`,
  시스템 화면 코드 `0x124C0`

## 적용 원칙

- 현재 단계에서는 글리프 치환 결과만 사용한다.
- 레코드 바이트, 카운터, 패딩, 포인터, 출력 좌표를 변경하지 않는다.
- 실행 검증은 초기 표시, 포커스 인, 포커스 아웃, 한 바퀴 순환, 재진입,
  지도 복귀를 모두 포함한다.
