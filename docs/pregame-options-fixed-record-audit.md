# 시작 전 옵션 고정 레코드 조사

일본판 Rev. A 원본만 읽어서 조사했으며 ROM은 변경하지 않았다.

## 메뉴 상태 테이블

`0x1016A`부터 각 항목은 `상태(2) + 표시 레코드 포인터(4) + 처리 함수
포인터(4)`인 10바이트 고정 엔트리다.

| 순서 | 상태 | 표시 레코드 | 처리 함수 |
|---:|---:|---:|---:|
| 0 | 0 | `0xEF41C` | `0x117AA` |
| 1 | 0 | `0xEF428` | `0x11E2C` |
| 2 | 0 | `0xEF42D` | `0x12064` |
| 3 | 0 | `0xEF433` | `0x1226E` |
| 4 | 0 | `0xEF43A` | `0x12386` |
| 5 | 0 | `0xEF441` | `0x1245A` |

이 테이블에는 별도의 포커스 문자열 포인터가 없다. 항목 선택 반전은 같은
표시 레코드를 다시 해석하거나 타일 속성을 바꾸는 경로일 가능성이 높으므로,
문자열을 복제해 해결하지 않는다.

## 표시 레코드

| 주소 | 일본판 원문 | 바이트 | 표시 칸 |
|---:|---|---:|---:|
| `0xEF41C` | ` 行動 ` | 7 | 4 |
| `0xEF423` | `行動` | 5 | 2 |
| `0xEF428` | `サウンド` | 5 | 4 |
| `0xEF42D` | ` 操作 ` | 6 | 4 |
| `0xEF433` | ` 索敵 ` | 7 | 4 |
| `0xEF43A` | ` 天候 ` | 7 | 4 |
| `0xEF441` | `システム` | 5 | 4 |

`0xEF41C`과 `0xEF423`은 같은 `行動`을 쓰지만 패딩과 표시 칸이 다른 별도
레코드다. 각각 메뉴와 옵션 화면 제목에서 참조되므로 합치거나 길이를 바꾸면
안 된다.

확장 글리프는 바이트를 그대로 슬롯 번호로 읽으면 안 된다. 출력 루틴
`0x81C8..0x81DA`의 계산은 다음과 같다.

- 1바이트 코드 `00..FC`: 해당 번호의 글리프
- `FD xx`: `0x0FD + xx`번 글리프
- `FE xx`: `0x1FD + xx`번 글리프

따라서 `FD 5A/FD 5B`는 `0x157/0x158`, 즉 `行/動`이다. 이를 단순
`0x15A/0x15B`로 해석하면 `天/候`로 세 칸 밀려 오독하게 된다.

`0xEF44B`의 ` MUSIC`은 일본판부터 영문이므로 그대로 보존한다.

## 직접 참조 확인

- `0xEF41C`: 상태 테이블 `0x1016C`
- `0xEF423`: 날씨 화면 코드 `0x117F8`
- `0xEF428`: 상태 테이블 `0x10176`, 게임 메뉴 테이블 `0x6234`,
  사운드 화면 코드 `0x11EDA`
- `0xEF42D`: 상태 테이블 `0x10180`, 게임 메뉴 테이블 `0x623E`
- `0xEF433`: 상태 테이블 `0x1018A`, 게임 메뉴 테이블 `0x6248`
- `0xEF43A`: 상태 테이블 `0x10194`, 게임 메뉴 테이블 `0x6252`,
  날씨 화면 코드 `0x10F30`
- `0xEF441`: 상태 테이블 `0x1019E`, 게임 메뉴 테이블 `0x625C`,
  시스템 화면 코드 `0x124C0`

## 적용 원칙

- 현재 단계에서는 글리프 치환 결과만 사용한다.
- 레코드 바이트, 카운터, 패딩, 포인터, 출력 좌표를 변경하지 않는다.
- 실행 검증은 초기 표시, 포커스 인, 포커스 아웃, 한 바퀴 순환, 재진입,
  지도 복귀를 모두 포함한다.

## 세부 화면 레코드

처리 함수의 직접 참조와 내부 상태 테이블을 함께 조사했다. 직접 `LEA`로
보이지 않는 선택값도 상태 테이블에서 다시 그려지므로 반드시 별도 레코드로
관리한다.

### 색적

| 주소 | 원문 | 역할 |
|---:|---|---|
| `0xEF502` | `索敵設定` | 제목 |
| `0xEF50A` | `索敵レベル  ` | 선택 행 |
| `0xEF514` | `初級` | 값 0 |
| `0xEF519` | `中級` | 값 1 |
| `0xEF51D` | `上級` | 값 2 |
| `0xEF521` | `下級` | 값 3 |

네 값은 글자 수가 같아도 서로 다른 주소다. 한 값만 고치면 순환 후 원문이나
다른 글자가 나타날 수 있다.

### 날씨

- 제목 `0xEF525`: 4칸 `天候設定`
- 선택 행 `0xEF52D`: 6칸이며 끝 공백까지 포함한다.
- 선택 행은 9바이트, 카운터 `5`로 실제 6칸이다. 다음 레코드 경계는
  `0xEF536`이다.

### 조작·시스템

- 조작 세부 레코드: `0xEF49E..0xEF4BC`
- 시스템 네 행: `0xEF4BD..0xEF4F2`
- 시스템 제목 및 영문 값: `0xEF4F3..0xEF501`
- 일본판부터 영문인 `REAL`, `AUTO`, `ON`, `OFF`는 보존한다.

전체 주소와 계산된 실제 글리프 슬롯은 `out/inventory/*_detail_records.json`
에서 확인한다. 원장 생성 도구는 `FD/FE` 변환식을 적용한 `glyph_indices`를
함께 출력한다.
