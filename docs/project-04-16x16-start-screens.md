# 남은 프로젝트 4번: 16x16 시작 화면 우선

## 순서 결정

사용자 결정에 따라 16x16 화면을 먼저 완료한다. 다음 항목은 이번 단계에서
제외하고 8x8 단계로 미룬다.

- 시나리오 선택 목록
- 지도 하단 정보
- 유닛명과 무장명
- 그 밖의 8x8 표와 상태창

## 보존 원칙

- 일본판부터 영문인 `CONTINUE`, `STANDARD`, `CAMPAIGN`은 변경하지 않는다.
- v029의 원본 16x16·8x8 글꼴과 `0xEF000..0xEFFFF` 레코드는 변경하지 않는다.
- 프로젝트 3에서 검증한 2 MiB 확장 글꼴과 별도 레코드 방식을 사용한다.
- 확장 영역은 서로 겹치지 않게 고정한다: 16x16 글꼴 `0x100000`,
  8x8 글꼴 `0x110000`, 확장 문자열 `0x120000`.
- 빌더는 16x16 글꼴이 8x8 시작 주소를 넘거나, 복제한 8x8 글꼴이
  한 바이트라도 달라지면 빌드를 거부한다. v053은 이 경계 검사가 없어
  16x16 추가 글리프가 8x8 글꼴을 침범했으므로 폐기한다.
- 화면의 표시 칸 수, 공백, 좌표 및 원래의 포커스 동작을 보존한다.
- 같은 레코드를 가리키는 초기·포커스 인·포커스 아웃·재진입 참조는
  누락 없이 한 묶음으로 전환한다.

## 첫 적용 묶음

게임 시작 전 메뉴의 일본어 항목을 대상으로 한다. 마지막 `開始`는 기능상
`개시`이며 기존 v029 표기가 정상이므로 별도 레코드로 바꾸지 않는다.

| 원문 | 표시 칸 | 한국어 레이아웃 |
|---|---:|---|
| ロード | 4 | `시나리오` |
| サウンド | 4 | `사운드 ` |
| ` 操作 ` | 4 | ` 조작 ` |
| ` 索敵 ` | 4 | ` 색적 ` |
| ` 天候 ` | 4 | ` 날씨 ` |
| システム | 4 | `시스템 ` |

초기 v036 조사에서 `0xEF446`의 `ゲーム`을 이 화면의 마지막 항목으로
잘못 분류했으나, 실제 마지막 항목은 `0xEF47E`의 `開始`다. 따라서
`ゲーム` 참조 변경은 제거하고 `開始`는 `개시`로 보존한다.

기존 레코드의 인접 데이터는 움직이지 않는다. 확장 영역에 독립 레코드를
만들고, 확인된 직접 포인터만 전환한다.

`ロード`는 게임 메뉴 일반 표시 `0xEF452`와 시작 전 선택 표시 `0xEF456`이
서로 다른 레코드다. 두 문맥을 혼동하지 않도록 게임 메뉴 직접 참조
`0x11842`는 3칸 `읽기 `, 시작 전 직접 참조 `0x6220`은 4칸
`시나리오`로 각각 별도 전환한다.

## 사운드 하위 화면

`0xEF446`은 초기 조사 라벨과 달리 원본 글리프가 `アラーム`이다. 사운드
화면의 직접 참조 `0x11EC8`만 별도 4칸 레코드 `알람  `으로 전환한다.
일본판부터 영문인 `NAME`, `MUSIC`, `ON`, 곡명은 변경하지 않는다.

## 조작·색적 하위 화면

- `操作設定`은 현재 한자음 치환만으로 `조작설정`이 정확하다.
- `USER/COM`, `NOT`, `USER`, `COM`은 일본판 원래 영문이므로 보존한다.
- 색적 제목과 `初級/中級/上級/下級`은 각각 `색적설정`,
  `초급/중급/상급/하급`으로 이미 정확하다.
- `索敵レベル  `의 가타카나 부분만 7칸 `색적레벨   `로 바꾸고 직접
  참조 `0x1231A` 하나만 전환한다.

## 날씨 하위 화면

- 제목 `天候設定`은 한자음 치환 상태에서 `천후설정`으로 표시되므로,
  4칸 `날씨설정`으로 바꾸고 직접 참조 `0x123D6`을 전환한다.
- 선택 행 `天候ルール `는 6칸을 유지한 `날씨규칙  `으로 바꾼다.
- 직접 참조 `0x12420` 하나만 별도 확장 레코드로 전환한다.

## 시스템 하위 화면

- 일본판 영문 `REAL`, `AUTO`, `ON`, `OFF`는 변경하지 않는다.
- `戦闘画面速度   `는 9칸을 유지한 `전투화면속도   `로 바꾸고
  직접 참조 `0x1250C`만 전환한다.
- `ヘックスライン  `은 9칸을 유지한 `헥스라인     `으로 바꾼다.
- 직접 참조 `0x1251A` 하나만 별도 확장 레코드로 전환한다.
- `敵ユニット性能表 `는 9칸을 유지한 `적유닛성능표   `로 바꾸고
  직접 참조 `0x12528`만 전환한다.
- `反撃武器を選択  `은 조사 `を`를 제거하되 9칸을 유지한
  `반격무기선택   `으로 바꾸고 직접 참조 `0x12536`만 전환한다.

## 시나리오 개시 메뉴

- `開始`는 기존 한자음 치환의 `개시`가 정확하므로 그대로 보존한다.
- `エディト`는 원본과 같은 4칸 `에디트 `로 바꾸고 직접 참조
  `0x6270` 하나만 전환한다.
- 이 메뉴 밖의 시나리오 목록과 8x8 레코드는 변경하지 않는다.
- `에디트`는 일반 상태에서 `개시` 아래에 이어지는 항목이 아니다. 모드 선택
  화면에서 `오른쪽, 왼쪽`을 입력한 뒤 `STANDARD`로 들어가면 마지막
  `개시` 항목이 숨김 맵 에디터 항목으로 교체된다. 일본판 테이블에서도
  `개시`와 `에디트`는 조건값 `1`, `2`의 상호 배타 항목이다.

## 상황표 화면

- 메뉴의 `状況表`는 원본 4칸을 유지한 `상황표 `로 표시한다.
- 화면 제목 `作戦`과 `目標`는 각각 2칸 레코드다. 출력 코드가 첫 레코드를
  그린 뒤 A0를 유지한 채 바로 다음 레코드를 그리므로, 확장 영역에서도
  `작전`과 `목표` 레코드를 반드시 인접 배치한다.
- `占 領 状 態`는 원본의 글자 사이 공백을 포함한 7칸을 그대로 유지해
  `점 령 상 태`로 표시한다.
- 직접 참조 `0x622A`, `0x10CDC`, `0x10CF6`만 전환한다. 상황표의 수치,
  영문 표제, 진영 목록 및 다른 메뉴 레코드는 변경하지 않는다.
- 상단의 `積雪度/通常/温帯`는 각각 원본 3/2/2칸을 유지한
  `적설량/정상/온대`로 표시한다. 한 칸인 `晴`은 늘리지 않고 `청`으로
  유지한다.

## 개발표 하단

- `開発画面`은 4칸 `개발화면`으로 표시한다.
- `開発画面 兵器種類選択`은 원본 14칸을 유지한
  `개발화면 병기종류선택   `으로 표시한다.
- 두 레코드 모두 확장 문자열 영역에 두며 원본 레코드는 수정하지 않는다.
- 유닛 선택 화면의 연속 레코드 `生産無/進化1/進化2/進化3/開発`은
  원본 3/3/3/3/2칸과 인접 순서를 유지해
  `생산무/진화1/진화2/진화3/개발`로 표시한다.
- 병기명처럼 작은 글씨로 표시되는 8x8 항목은 이번 16x16 단계에서
  변경하지 않는다.

## 메인 모드 선택 메뉴

- 일본판부터 영문인 `CONTINUE`, `STANDARD`, `CAMPAIGN`, `MODE`는
  변경하지 않는다.
- `A主力 C補助`, `A補助 C主力`의 일본어 부분은 기존 한자음 글리프에서
  각각 `A주력 C보조`, `A보조 C주력`으로 정확히 표시된다.
- 따라서 이 메뉴는 별도 레코드나 포인터를 추가하지 않고 현 상태를
  완료 상태로 보존한다.

## 유닛 행동 메뉴

- 기본 행동의 `이동/공격/점령/보급/합류/보충`은 기존 한자음 글리프에서
  정확히 표시된다.
- 두 번째 행동 메뉴의 `성능/처분/진화/개량/행군`도 기존 한자음
  글리프에서 정확히 표시된다.
- 표시 칸과 상태 전환을 건드릴 이유가 없으므로 별도 레코드 및 포인터
  패치를 추가하지 않는다.

## 게임 메뉴

- `セーブ`는 원본과 같은 3칸 `저장 `으로 바꾼다.
- 이 항목은 일반·선택 반전에서 같은 레코드를 사용하므로 직접 참조
  `0x11838` 하나만 별도 확장 레코드로 전환한다.
- 제목 `行動`은 이 화면 문맥에 맞춰 2칸 `게임`으로 바꾸고 직접 참조
  `0x117F8`만 전환한다.
- `降伏`은 2칸 일반 표시 `항복`과 3칸 선택 표시 `항복 `을 분리해
  직접 참조 `0x1186E`, `0x1184C`를 각각 전환한다.
- `中止`는 현재 `중지`가 정확하므로 변경하지 않는다.
- 저장 번호 제목은 일본판 영문 `No.`를 보존해 8칸 `저장 No.선택`으로
  바꾸고 직접 참조 `0x11AB0`을 전환한다.
- 읽기 번호 제목도 8칸 `읽기 No.선택`으로 바꾸며, 두 진입 경로의 직접
  참조 `0x603E`, `0x118F4`를 함께 전환한다.
