# v014 공용 8x8 글리프 치환 후보 — 폐기

> 실행 중 Standard Scenario 로드 후 장시간 정지가 관찰되어 폐기했다.
> 원인은 `0x3850E+0x800` 이후의 전투 표시용 DMA 타일을 8x8 글리프로
> 잘못 간주해 치환한 것이다. 이 ROM을 부모나 테스트 기준으로 사용하지 않는다.

- 부모 기준: 일본판 Rev. A 원본 + v013의 확정 16x16 글리프 목록
- 방식: 문자열·포인터·레코드는 변경하지 않고, 같은 문자 인덱스의 원본
  8x8 글리프 그림만 M8x8 한글 자형으로 치환했다.
- 당시 8x8 원본 글꼴을 `0x3850E`, 크기 `0xA90`로 판단했으나 이는 잘못된 경계였다. 이후 68K 로더 분석으로 실제 업로드 크기는 `0x548`바이트(169글리프)임이 확정되었다.
- 원본 글꼴 직접 참조: `0x008146`, `0x008200`, `0x0106AE` (변경 없음)
- 출력: `out/fixed-record-kana-kanji-8x8-v014.md`
- 크기: 1,048,576 bytes
- SHA-256: `3EFA2DE7376AFE8AE24C9E3C5B5CBC561FF318B45D1584153404E72C48193676`
- 메가드라이브 체크섬: `0x7441`
- 8x8 치환 글리프: 250개
- 변경된 레코드: 0
- 허용 범위 밖 변경: 0
- UI 레코드 영역 `0xEF000..0xEFFFF`: v013과 완전 동일
- v013 대비 변경은 체크섬 2바이트와 원본 8x8 글꼴 범위 안에만 존재한다.

## 안전 조건

- `0xA7..0xFF` 문자열 코드를 새로 할당하지 않았다.
- 문자열 길이, 표시 셀 수, 레코드 수와 순서가 모두 그대로다.
- 원본 영문/숫자/기호 인덱스는 치환 목록에 없는 한 그대로다.
- 실행 검증 전 후보이며, 사용자 확인 전에는 안전 태그로 승격하지 않는다.
